## Critical Breaking Changes Implemented

### 1. Authentication Changes (No OAuth/MFA)
- Replaced Cognito OIDC with native email/password auth
- Password hashing uses SHA-256 + secret (upgrade to bcrypt recommended)
- Session tokens stored server-side in D1 database
- No MFA support (Cloudflare doesn't offer native MFA for Workers)

### 2. Password Reset Flow
- New `/auth/reset-password` page for requesting reset
- New `/auth/reset-confirm` page for setting new password
- Reset tokens stored in `preferences_json` field, expire in 24 hours
- Emails sent via existing SES infrastructure

### 3. Analytics Migration to DuckDB-Wasm
- Replaced AWS Athena with client-side DuckDB queries
- Parquet files served from R2 via `/api/analytics/r2` endpoint
- `src/lib/analytics-client.ts` provides client-side query interface
- Falls back gracefully when DuckDB-Wasm unavailable

## Next Steps for Deployment

1. **Set required secrets:**
   ```bash
   # Generate a secure random secret (recommended: 32+ bytes)
   SESSION_SECRET=$(openssl rand -hex 32)

   # Set it in Cloudflare Workers
   echo "$SESSION_SECRET" | npx wrangler secret put SESSION_SECRET

   # For staging environment
   echo "$SESSION_SECRET" | npx wrangler secret put --env staging SESSION_SECRET

   # Verify secrets are set
   npx wrangler secret list
   ```

2. **Run D1 schema migration (both migrations):**
   ```bash
   # Run base schema
   npx wrangler d1 execute user-auth-db --file ./migrations/0001-auth-schema.sql --remote

   # Run optimizations
   npx wrangler d1 execute user-auth-db --file ./migrations/0002-d1-optimizations.sql --remote
   ```

3. **Deploy to Cloudflare Workers:**
   ```bash
   pnpm cf:build && pnpm cf:deploy:free
   ```

4. **Migrate existing users (one-time):**
   ```bash
   # Run the migration script after Cognito is configured
   pnpm migrate:dynamodb-to-d1
   ```

5. **Update GSC sync to export parquet:**
   ```bash
   # Run GSC sync to generate parquet files
   pnpm gsc:sync

   # Upload to R2 analytics bucket
   npx wrangler r2 object put cloudless-analytics/lake/gsc-snapshot.parquet --file ./out/gsc-snapshot.parquet
   ```

## SESSION_SECRET Configuration Guide

### Why SESSION_SECRET is Required

The `SESSION_SECRET` environment variable is used for password hashing in the D1 authentication system. It is combined with the user's password before hashing with SHA-256 to prevent rainbow table attacks.

### Setting the Secret

```bash
# Production
echo "your-32-byte-hex-secret" | npx wrangler secret put SESSION_SECRET

# Staging
echo "your-32-byte-hex-secret" | npx wrangler secret put --env staging SESSION_SECRET
```

### Session Secret Requirements

- **Minimum length:** 32 characters (256 bits recommended)
- **Format:** Hex string or base64 encoded
- **Storage:** Cloudflare Workers secrets (encrypted at rest)
- **Never commit:** Do not add to version control or .env files

### What Happens Without SESSION_SECRET

- Registration will fail with "Authentication not configured"
- Login will fail with "Authentication not configured"
- Password reset will fail with "Authentication not configured"
